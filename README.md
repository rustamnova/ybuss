# Ybuss

**Автобусы с нескольких остановок — в одном Telegram-боте.**

Личный Telegram-бот [@ybuss_bot](https://t.me/ybuss_bot): прибытие автобусов по
сохранённым остановкам Яндекс Карт. Работает на Linux-сервере независимо от
домашнего компьютера. Python 3.10+, только стандартная библиотека.

Автор проекта: [rustamnova](https://github.com/rustamnova). Исходный код открыт
под [Apache License 2.0](LICENSE); уведомление об авторстве — [NOTICE](NOTICE).
Для собственного запуска создай своего бота и получи свой токен через
[@BotFather](https://t.me/BotFather). Существующий бот — личный экземпляр,
а не общий сервис для всех пользователей.

## Использование

- `/start` — меню. Первый пользователь в личном чате становится владельцем;
  другие аккаунты не получают доступ к его остановкам.
- **🚌 Прибытие** или `/bus` — получить данные всех сохранённых остановок.
- **📍 Остановки** или `/stops` — названия и ссылки.
- **➕ Добавить остановку** — отправить полную или короткую HTTPS-ссылку Яндекс Карт.
- **➖ Удалить остановку** — выбрать название кнопкой; также доступно `/remove N`.

До 10 остановок. По умолчанию добавлена «Жилой комплекс Мытищи Лайт».
Состояние и владелец сохраняются при перезапуске.

Ответ содержит номер, направление и до трёх ближайших прибытий:

🚌 **509** · 🟢 **через 7 мин**<br>
*→ Метро Медведково · 2B · в 15:07*<br>
Далее: 🕒 20 мин (15:20)

В Telegram номер и ближайшее ожидание выделяются жирным, направление и часы —
курсивом. 🟢 означает прогноз, 🕒 — расписание.

Часы берутся из абсолютного времени события, минуты рассчитываются на момент
ответа, с округлением вверх. Используется часовой пояс остановки, включая
переход через полночь. Пример выше вымышленный.

## Источник и ограничение limited

Бот запрашивает публичную HTML-страницу остановки и читает вложенный JSON
`script.state-view → config.masstransitStop`. В событиях `BriefSchedule.Events`
поле `Estimated` используется как прогноз, `Scheduled` — как расписание.
При наличии обоих берётся прогноз. Назначение обозначений прогноза и расписания
описано в [справке Яндекса](https://yandex.ru/support/m-maps/ru/transport).

31 октября 2026 на сервере Chromium возвращал страницу `limited`, а обычный
HTTPS-запрос с того же сервера получал HTTP 200, название остановки, актуальное
`currentTime` и события `Estimated`. Это подтверждает работающий путь получения
данных, но не устанавливает точную причину ограничения Chromium. Браузерный
способ заменён прямым чтением страницы. Chromium, прокси и аккаунт Яндекса для
бота больше не требуются.

Это разбор публичной страницы, а не документированный стабильный API.
Формат и доступность могут измениться. Ограничения не обходятся: при `limited`,
HTTP 403 или 429 бот выдерживает общую паузу 5 минут и сообщает о проблеме.
Кеш одной остановки — 30 секунд; при выдаче указано время получения.
После истечения кеша старый ответ при ошибке не выдаётся. Проверяется свежесть
`currentTime`: ответ старше 180 секунд или более чем на 60 секунд из будущего
отклоняется. На сервере нужны правильные часы.

Сетевые переходы разрешены только между HTTPS-страницами `/maps/` на доменах
Яндекса; ссылки на другие сайты и локальные адреса отклоняются. Ответ ограничен
4 МБ, сетевой таймаут — 20 секунд.

## Установка на Linux с systemd

### Где взять сервер

Нужен постоянно включённый Linux-сервер с доступом в интернет. VPS можно
арендовать, например, здесь:

- [Aeza — выбрать сервер](https://aeza.net/?ref=688404)
- [HostVDS — выбрать сервер](https://hostvds.com/?affiliate_uuid=8c78e54c-a60e-4a8a-a7c7-1bda271aa343)

Это партнёрские ссылки автора: при оформлении услуги по ним автор может получить
вознаграждение. Можно использовать любого другого провайдера — привязки к этим
площадкам нет. Тарифы и доступность регионов проверяй на сайтах провайдеров.

Требования: Linux с systemd, Python 3.10+, CA-сертификаты, DNS и исходящий HTTPS
к Telegram и Яндекс Картам. Часы сервера должны синхронизироваться.
Для небольшого личного экземпляра ориентир при выборе VPS — 1 vCPU и 512 МБ
RAM; это стартовый ориентир, а не результат нагрузочного тестирования.
Домен, входящий веб-порт и установленный браузер не требуются.

### Первый запуск

Ниже пример для **нового сервера Ubuntu 24.04 / Debian 12**, команды выполняются
от `root`. Если экземпляр уже установлен, используй порядок обновления ниже.

```sh
apt-get update
apt-get install -y python3 git ca-certificates
useradd --system --home-dir /var/lib/yandexbus --shell /usr/sbin/nologin yandexbus
git clone https://github.com/rustamnova/ybuss.git /opt/yandexbus
install -d -m 750 -o root -g yandexbus /etc/yandexbus
install -m 640 -o root -g yandexbus /dev/null /etc/yandexbus/token
```

Открой `/etc/yandexbus/token` в редакторе и сохрани **только свой токен**,
полученный в BotFather. Не вставляй его в команды, Git и журналы.
Затем проверь код и установи службу:

```sh
cd /opt/yandexbus
python3 -m unittest discover -s tests -v
install -m 644 deploy/yandexbus.service /etc/systemd/system/yandexbus.service
systemctl daemon-reload
systemctl enable --now yandexbus
systemctl status yandexbus --no-pager
journalctl -u yandexbus -n 30 --no-pager
```

Открой **своего** бота в Telegram и первым нажми `/start`, чтобы закрепить
владельца. Пришли ссылку на нужную остановку и нажми **🚌 Прибытие**.

Служба работает от отдельного пользователя, без открытого входящего порта,
через Telegram long polling. `StateDirectory` создаёт `/var/lib/yandexbus`.
Токен читается при первом запросе Telegram, `state.json` хранит владельца,
остановки и смещение обновлений. Эти файлы не входят в репозиторий.
Переменная `YANDEXBUS_TOKEN_FILE` меняет путь к файлу токена;
`STATE_DIRECTORY` — каталог состояния. Нельзя запускать два polling-процесса
с одним токеном. Для нового развёртывания владелец должен первым нажать `/start`.

При обновлении сохранить закрытую резервную копию кода и `state.json` вне Git,
остановить службу, заменить оба Python-файла, запустить тесты и службу.
Не удалять `state.json`: это сбросит владельца и остановки.
При установке из Git можно обновить код через `git pull --ff-only` в
`/opt/yandexbus`, пока служба остановлена. Если изменился файл службы,
повторно установить его и выполнить `systemctl daemon-reload` перед запуском.

## Проверка

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile bot.py yandex.py
```

Тесты выполняются без сети и токена: выбор прогноза вместо расписания,
полночь, устаревшие данные, другой ID остановки, кеш и запрет повторов при
ограничении, безопасные ссылки и раскрытие короткой ссылки.
Сам по себе успешный тест не подтверждает доступность Яндекса.

Проверка источника без Telegram, из каталога проекта:

```sh
python3 - <<'PY'
from yandex import Client, format_stop
url = 'https://yandex.ru/maps/213807/boltino/stops/stop__9675162/?tab=overview'
print(format_stop(Client().get(url)))
PY
```

Секреты, исходные HTML-ответы с техническими полями Яндекса и личное состояние
не публикуются.
